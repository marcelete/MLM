1. LO QUE YA HICIMOS  ✅
────────────────────────────────────────────────────────────────

1.1  INFRAESTRUCTURA Y DEPLOY
  • Repositorio Git creado en marcelete/MLM
  • Hosting estático en GitHub Pages con auto-deploy por
    GitHub Actions (cada push a la rama default redepliega solo)
  • Variables de entorno (Supabase URL, anon key, WhatsApp)
    configuradas como GitHub secrets
  • Base de datos en Supabase (tier gratuito) con schema
    completo aplicado: profiles, categories, products,
    product_variants, customers, orders, order_items,
    visitor_sessions, analytics_events
  • RLS (Row Level Security) habilitado con políticas por rol
  • Branding del sitio en español (textos, monedas en ARS,
    fechas en formato es-AR)

1.2  PÁGINAS PÚBLICAS (sin login)
  • Home con hero, productos destacados y categorías
  • Catálogo con filtros (categoría, talla, color, precio,
    búsqueda)
  • Detalle de producto con variantes (color/talla/modelo),
    galería de imágenes, tabla de precios por método de pago
  • Carrito persistente (CartContext + localStorage)
  • Cart Drawer lateral
  • Checkout en 3 pasos (Datos → Pago → Confirmar)
  • Página de confirmación con número de pedido
  • Footer con info de contacto

1.3  AUTENTICACIÓN Y ROLES
  • Login y registro con email + contraseña (Supabase Auth)
  • 3 roles definidos: 'comprador', 'admin', 'superadmin'
  • Trigger SQL que crea profile automáticamente al registrarse
  • AuthContext con persistencia de sesión y refresh de token
  • Página de login pública y página de login admin separada
  • Cuenta de usuario "Mi cuenta" con historial de pedidos

1.4  PANEL ADMIN (rol admin y superadmin)
  • Dashboard con KPIs (órdenes hoy, ingresos, pendientes)
  • Productos: CRUD completo + gestión de stock por variante
  • Stock: vista de inventario con alertas
  • Pedidos: listado, filtros por estado, vista de detalle,
    cambio de estado
  • Clientes: listado y vista de cliente
  • Finanzas: reportes básicos de ingresos
  • Analytics: tracking interno de sesiones y eventos

1.5  PANEL SUPERADMIN
  • Gestión de usuarios (listar, cambiar roles)

1.6  GENERACIÓN DE PDF  (Implementado en sesión actual)
  • Librería jsPDF integrada
  • src/lib/pdf.js con dos generadores:
      - generarTicketPDF(): A4 con detalle completo del pedido,
        productos, totales, método de pago, datos del cliente
      - generarEtiquetaPDF(): 10x15cm con destinatario,
        teléfono, dirección, checkboxes Frágil/Urgente
  • Botones "Imprimir ticket" e "Imprimir etiqueta" en el
    detalle de pedido del panel admin
  • Order items se cargan desde la base al abrir el modal

1.7  EMAILS TRANSACCIONALES  (Implementado en sesión actual)
  • Edge Function supabase/functions/send-email
  • Integración con Resend.dev (3.000 emails/mes gratis)
  • 4 templates HTML responsivos con branding MLM:
      - compra_confirmada (al crear orden)
      - pago_confirmado (al pasar a "Confirmado")
      - orden_enviada (al pasar a "Enviado")
      - orden_entregada (al pasar a "Entregado")
  • CheckoutPage dispara email al cliente al crear orden
  • OrdersPage dispara email al cambiar estado
  • Helper src/lib/email.js que invoca la edge function
    sin bloquear el flujo si falla

1.8  WEBHOOK MERCADO PAGO  (Implementado en sesión actual)
  • Edge Function supabase/functions/mercadopago-webhook
  • Recibe notificaciones de pago, consulta el detalle a la API
    de MP y actualiza el estado de la orden automáticamente
  • Loguea todos los eventos en mercadopago_eventos
  • Mapea estados MP → estados internos:
      approved → confirmed
      rejected/cancelled → cancelled

1.9  SISTEMA DE REVIEWS  (Implementado en sesión actual)
  • Tabla reviews con: rating 1-5, comentario, verified flag,
    respuesta del admin, UNIQUE por (orden, producto)
  • Vista product_rating_summary (promedio y conteo)
  • RLS: lectura pública, escritura solo del propio usuario,
    edición admin
  • Componente StarRating reutilizable (lectura e input)
  • Componente ProductReviews integrado en detalle de producto
  • Modal "Opinar sobre tu compra" en AccountPage para órdenes
    entregadas, con flag de compra verificada

1.10 AUDIT LOGS  (Implementado en sesión actual)
  • Tabla audit_logs con: user_id, email, action,
    resource_type, resource_id, changes JSONB
  • Helper src/lib/audit.js: logAction()
  • RLS: solo superadmin puede leer
  • Integrado en OrdersPage (cambios de estado de pedidos)

4. LIMITACIONES TÉCNICAS A TENER EN CUENTA
────────────────────────────────────────────────────────────────

  • GitHub Pages es 100% estático: cualquier código de servidor
    debe ir como Supabase Edge Function (gratuito)
  • Cron jobs requieren Supabase Cron (también gratuito) —
    aún no usamos ninguno
  • El plan free de Supabase incluye:
      - 500 MB de base de datos
      - 1 GB de Storage
      - 50.000 Auth users
      - 500.000 invocaciones de Edge Functions/mes
    suficiente para el primer año de operación

  • Resend.dev plan free:
      - 3.000 emails/mes (100/día)
      - Cuando se supere, costo es USD 20/mes por 50.000

  • Bundle JS actualmente 720 KB (gz 217 KB). Se puede mejorar
    con code splitting más adelante.
